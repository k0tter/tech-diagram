# ER 図・UML クラス図の描き方

ER 図/UML クラス図/コンポーネント図を描くときに 1 回 Read する。
ワークフロー(スペック→ビルド→検証→ --optimize)・meta・legend・配置原則は
SKILL.md と同一。ここには差分だけ書く。**シーケンス図は対象外**(時間軸レイアウトは
このエンジンの守備範囲外。頼まれたら別ツールを案内する)。

## 箱ノード(エンティティ / クラス)

```json
{"id": "orders", "shape": "entity", "title": "orders",
 "rows": ["PK id: bigint", "FK customer_id", "status: enum"], "col": 1, "row": 0}
```

- `title` = 見出し(太字)。UML のインターフェース/抽象クラスは
  `"stereotype": "interface"` / `"stereotype": "abstract"` を指定する
  (`«...»` 行を自動生成し、クラス名を斜体にする。title への直書きは避ける)
- `rows` = 属性/フィールド区画、`rows2` = メソッド区画(UML で使用。区画線が入る)。
  どちらも省略可 — インターフェースは `rows2` のみでよい(空区画は描かれない)
- 寸法は内容から自動計算(w/h で上書き可)。ラベルは箱の中なので
  **下辺も配線に使える**(アイコンと違い 4 辺自由)
- icon は不要。AWS アイコンと同一図に混在させてもよい
- スキーマ/パッケージの囲みは `containers.type: "generic"` を使う

## 関係線(組み込み kind。legend にもこの名前で載せる)

| kind | 意味 | 向き(src → dst) |
|---|---|---|
| `er_11` | 1 対 1 | どちらでも |
| `er_1n` | 1 対 多 | **1 側 → 多側**(クロウズフットが dst に付く) |
| `er_0n` | 1 対 0..多 | 1 側 → 0..多側 |
| `er_01n` | 親 0..1 対 子 多(nullable FK) | **親 → 子**(○| が src、クロウズフットが dst) |
| `er_11n` | 親 1 対 子 多(必須 FK) | **親 → 子**(|| が src、クロウズフットが dst) |
| `er_nn` | 多対多(両端クロウズフット)| 概念モデルのみ。物理設計では中間テーブルに解決 |
| `uml_inherit` | 継承 | **子 → 親**(△が親側) |
| `uml_implement` | 実現(implements) | **実装クラス → インターフェース** |
| `uml_assoc` | 関連 | 参照する側 → される側 |
| `uml_compose` | コンポジション | **全体 → 部分**(◆が全体側) |
| `uml_aggregate` | 集約 | 全体 → 部分(◇が全体側) |
| `uml_depend` | 依存(点線) | 依存する側 → される側 |

UML の多重度(1 / 0..1 / 1..* 等)は `src_label` / `dst_label` に書く。
線中央の関係名・ロール名は `label` と併用できる。色分けが必要なら AWS 図と
同様に `kinds` でカスタム定義してもよい。

## レイアウトの定石

- **ER**: 親テーブル→子テーブルを左→右に(customers → orders → order_items)。
  中間テーブル(多対多の解決)は両親の間の列に置く
- **UML 継承**: 親(インターフェース)を上の row、子を下の row に。
  兄弟クラスは親の左右対称に置くと実現線が対称に出る
- 箱は高さがまちまちでも行の高さが自動で広がる。1 つの行に背の高い
  エンティティを集めすぎない(行が間延びする)
- AWS 図と同じく交差はバリデータの目安内なら微調整不要。`--optimize` も有効

## 多対多の注意

- 物理設計では M:N を直接引かず**中間テーブル**(例: order_items)で解決する。
  概念モデルで直接引くときだけ `er_nn`
- **er_*・uml_* に `bidir` を併用しない**(矢じり記法が壊れる。ビルダーが WARN)

## 自己参照(社員→上司 など)

- `src` と `dst` に同じノード id を書けば、側面のコの字ループで描かれる
  (例: `{"id": "r9", "src": "employees", "dst": "employees", "kind": "er_1n",
  "label": "上司"}`)。ラベルはループの縦線上に載る
- コンテナへの自己ループは不可(ノードのみ)
